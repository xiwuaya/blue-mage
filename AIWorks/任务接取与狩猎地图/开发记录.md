# 任务接取地图与狩猎多点地图 · 开发记录

[PR #1](https://github.com/xiwuaya/blue-mage/pull/1) 给 238 条学习途径增加了任务接取或对话解锁地点。其中 6 条理符、职业任务单独配置接取人，其余 232 条复用 147 个副本或挑战的解锁记录。另有 28 条狩猎途径，共用 25 只怪物的候选刷新点。下文按本 PR 的版本说明；FATE 后续迁移和主线开关见 [PR #2](https://github.com/xiwuaya/blue-mage/pull/2)。

## 新增学习途径时怎样填写 spells.json

编辑目标技能的 `method` 数组，每个元素是一条途径。技能外层结构沿用原格式。**每条新途径必填 `type`（下表的字符串）和 `level`（数字），再加表中对应的必填项。** `note`、`color` 是可选的说明和颜色。表中“必填”指类型与展示约定；CSV 导入器不会替你校验完整性。

| type | 另须填写的字段 | 何时补充地图数据 |
| --- | --- | --- |
| `map` | `map` 地图名、`mob` 怪名 | 要显示野怪地图时填 `position: [X,Y]`，已有三维坐标也可保留。可选 `rank`。 |
| `hunt` | `map`、`mob` | 可选 `rank`（例如 A）。完整地图在狩猎共享表登记；只有旧单点时兼容途径自身的 `position`。 |
| `levequests` | `map`、`mob` | 若要展示接取人，填 `questStart`。外层 `map` 是战斗地图。 |
| `jobquest` | `name` 任务名、`mob` | 接取信息写在本途径的 `questStart`。 |
| `dungeon`、`raid`、`trail`、`carnivale` | `name` 内容名、`mob` | 需要解锁地图时，按内容名登记共享解锁记录；已有记录可直接复用。讨伐战的实际拼写为 `trail`。 |
| `treasure`、`guildhests` | `name`、`mob` | 通常只写基础途径；有具体接取点时可用 `questStart`。 |
| `fate` | `map`、`name` 事件名、`mob` | #1 阶段保留旧的可选单点 `position`。采用 #2 后，新事件登记在 `fate-spawns.json`。 |
| `special` | `text` 说明文字 | 纯文本途径无需地点。 |

**区分三个坐标字段。** `method.position` 是一次战斗的单点，`method.questStart.position` 是一个 NPC 的接取点，`hunt-spawns.json` 中的 `positions` 是一只怪的全部候选点，例如 `[[X1,Y1],[X2,Y2]]`。值使用游戏地图显示的数值坐标。没有地点时可省略可选字段，不用给其他技能补空对象或空数组。

下面是库中一条实际的理符途径，省略了可选的颜色和备注。玩家在伊修加德基础层接取任务，随后前往库尔札斯西部高地战斗。

```json
{
  "type": "levequests",
  "level": 50,
  "map": "库尔札斯西部高地",
  "mob": "焚书任务：回收禁书«假面怪物» - 自由假面",
  "questStart": {
    "npc": "艾洛因",
    "map": "伊修加德基础层",
    "position": [10.1, 10.3]
  }
}
```

## 采集、匹配与更新

1. **单条任务或共享解锁。** 写了 `questStart` 就必须给出 `npc`、`map`、`position`。共享解锁记录使用同一结构，以 `method.name.trim()` 为键；两种记录同时存在时，整条 `questStart` 优先。真实开放任务可补 `quest`（任务名）、`questId`（数字行号）；直接对话开放的共享记录省略这两项，页面会标为“对话解锁”。地图存在多个楼层或别名匹配不准时填写 `mapKey`，它优先于地名查表。示例可查 `duty-unlocks.json` 的“乐欲之所瓯博讷修道院”，其接取地点为剧场艇初见号道具间，地图编号 420。
2. **核对接取 NPC。** 先按副本名称和难度确认开放任务；章节式开放可记录该章起始任务，有多种方式时记录一条可行路线。按国服 Quest 行号查 Issuer{Start} 和 Issuer{Location}，关联 ENpcResident、Level、Map 核对 NPC、实际楼层与游戏显示坐标。避免把进本入口或任务交付点当成接取点。[国服解包快照](https://github.com/thewakingsands/ffxiv-datamining-cn/tree/ae29be8b21a32329e3356709422427540bf7e364) · [副本前置条件对照](https://ff14.huijiwiki.com/wiki/模块:Instance/Preq)
3. **狩猎。** `hunt-spawns.json` 以完整 `mob` 为键，每项必填 `map` 和非空 `positions`。复用记录时，途径与记录的地图名须一致；未匹配时程序只尝试途径上的旧单点。A级按区域和怪名筛选 Scout 的 valid_mobs；B 级按 PuniMapper 收录专属点及额外点，S 级取该地区的 S 级候选点。更新时去掉重复点，保留所有已确认的位置。这两张共享表随仓库提交，日常构建不会重新采集它们。[Scout 点位对照](https://github.com/pm-wobbuffet/scout/blob/11ae48b79098d6564c757394ffc9120e815113e0/resources/csv/SPAWN_POINT_MOBS.csv) · [PuniMapper](https://punimapper.ffxivhunts.com/about/)
4. **增量导入。** 可在 `tools/data/method_updates.csv` 添加基础途径，然后运行 `node tools/update/update-methods.js`。CSV 只能写已有列，`position` 可写成带引号的逗号分隔坐标。嵌套 `questStart`、共享表和 `special.text` 需直接维护 JSON。先核对写回的 `spells.json` 再清理已处理的 CSV 指令；脚本不会因已有成功状态而跳过该行，重复执行会再次插入。
5. **验证。** 在项目根目录运行 `node tools/update/update-map-keys.js`，检查新地名均解析到正确地图，随后运行 `yarn build`。分别从主列表及静态技能页打开同一条途径：任务图标应定位到接取 NPC；狩猎弹窗显示的点数应与共享表一致。涉及发布路径时再运行 `yarn build:subpath` 核对深链。
