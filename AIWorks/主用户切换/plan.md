# 多人模式主用户切换（plan.md）

> 记录人：AI Agent
> 日期：2026-11-05
> 状态：已实施，结果见同目录 [result.md](result.md)
> 评审方式：grill-me 追问式访谈，共三轮，关键分歧均已由维护者拍板

---

## 1. 要解决的问题

多人模式里「我」硬绑定用户 1：主页勾选状态（`spell-status`）永远是用户 1 的存档，
队友 2–20 只是贴进来的静态文本。当我想**替某个队友记录进度**、或**从他的视角看还缺
哪些技能**时，做不到——除非把他的数据贴进用户 1 槽位，而那会覆盖掉自己的存档。

期望：在多人模式配置面板里，能把任意一个队友「设为我」，此后主页的勾选、同步、
统计都跟随他；原有数据不丢失，随时可切回。

## 2. 方案选型（关键决策及理由）

### 决策 1：面板内「设为我」，否决 `/user/{user_id}` 路径路由

最初设想是「每个用户名右侧加跳转选项，路由到 `/user/{user_id}`」。否决理由
（这是本次评审里最值得留档的认知差）：

- **`/spell/{action_id}` 不是路由**。它是构建期由 `tools/pagegen/generate-spell-pages.js`
  烧进 `dist/spell/<id>/index.html` 的静态文件，托管层只做「路径 → 磁盘文件」映射。
  它成立依赖两个前提：ID 集合构建期完全已知（来自仓库内 spells.json）；页面内容
  构建期完全可算（与访客无关）。
- **`/user/{user_id}` 两条都不满足**。用户集合是访客在运行时于自己浏览器里产生的
  （localStorage），构建期不知道有哪些 id、更拿不到内容。要让 `/user/任意值`
  返回页面，只能三个分发渠道（EdgeOne / Cloudflare / GH Pages 子路径）都配
  rewrite 兜底壳页，GH Pages 还得走 404.html hack——而壳页内容终究要 JS 现读
  localStorage 填充，**路径本身不携带任何信息，纯装饰**。
- 全站没有 vue-router，唯一的 URL 先例是 `?search=` 深链（App.vue:92）。
  为单一功能引入路由层 + 三渠道托管配置，成本与收益完全不成比例。

### 决策 2：主用户指针模型，否决槽位对调

比较过两种实现：

| | 指针模型（选定） | 槽位对调 |
| --- | --- | --- |
| 原理 | 新增「谁是主用户」指针，数据原地不动 | 把用户 1 槽位与队友槽位内容整体互换 |
| 切换 | 无损、可逆、即时 | 无损但需双向往返才能切回 |
| 代价 | `useSpellSync.ts` 里所有「用户 1 特判」要泛化为「指针所指槽位」 | UI 结构几乎不动，改动面小 |

选指针模型：数据零挪动是最强的无损保证，「切换」这个高频动作的可逆性优先于
实现量。泛化改动集中在一个文件里，边界清晰。

### 决策 3：只做单标签页，双开场景整体推迟

评审中曾提出「开两个网页、各自设不同主用户」，分析后撤回。原因：

- `spell-status` 是单键共享存储，两个指向不同用户的标签页在**写路径**上结构性冲突；
- 现状本就存在「双标签页静默互覆」隐患（`setting.ts` 是裸 localStorage 读写，
  无 `storage` 事件监听，后写者整体覆盖），指针模型会放大它；
- 可行的替代（`?as=` 预览页 / sessionStorage / storage 事件合并）都有实打实的
  复杂度，收益撑不起本期体量。

**本期不做**：预览页、`?as=` 参数、跨页同步、跨设备分享链接。存量互覆隐患
保持现状，不在文案里承诺任何多开行为。

### 决策 4：指针与三态显隐正交，所指用户可被隐藏

「应用该配置」本来就会把不在推荐队伍里的用户 1 设为隐藏（PartyModal.vue:348），
所以「主用户处于隐藏态」不是边界情况，是正常路径。处理原则：

> **不为「指针所指 + 隐藏」这个组合写任何新逻辑**，完全继承现行
> 「用户 1 被隐藏」的行为。

评审中曾把该语义误述为「主页改动暂不向队友同步」，已纠正。现行隐藏语义的
准确表述（对任何用户，含泛化后的所指用户）：

1. **不进计算池**：未掌握计数、最优组队、多队伍推荐全部跳过（useSpellSync.ts:121、
   PartyModal.vue:224-234）；
2. **他自己的文本框冻结**：主页打勾不再刷新他的数据串（useSpellSync.ts:70 的
   `!== 2` 守卫）；主页存档 `spellStatus` 照常记录；
3. **取消隐藏时立即对齐**：文本框按当前存档重新生成（watcher，useSpellSync.ts:94-103）。

注意：主页向**其他可见队友**的同步只看队友各自的三态（useSpellSync.ts:213 的
`continue`），与所指用户是否隐藏无关。

## 3. 数据模型

新增持久化指针（`src/lib/useSpellSync.ts`，模块级单例随现有状态一起初始化）：

```ts
const mainUserSlot = ref<number>(loadSetting<number>("main-user-slot") ?? 0); // 0 = 用户 1
```

- 指针所指槽位 = 「我」：槽 0 的文本是 `user1Spells`，槽 k（k≥1）的文本是
  `partyData[k-1]`。所指槽位的文本与 `spellStatus` 双向绑定，即现有用户 1
  全套特判的泛化。
- 存量用户无 `main-user-slot` 键，默认 0，无需迁移。
- 预渲染读不到 localStorage，HTML 呈现默认（用户 1）状态；客户端本就整体
  重渲染（ADR 0005），无一致性风险。

### 切换动作 `setMainUser(slot)` 的统一算法

1. `slot === 当前指针` 时 no-op。
2. **落盘旧所指槽位**：把当前 `spellStatus` 解析出的未掌握编号串写回旧所指槽位
   的文本（槽 0 → `user1Spells`，槽 k → `partyData[k-1]`）。**无视其三态**——
   可见时这是幂等空转（watcher 一直在同步）；隐藏时这一步把冻结期间的勾选
   收敛进他的数据串，否则这些勾选会在存档被覆盖时静默丢失。
3. **重建存档**：从新所指槽位的文本解析出编号集合，重建 `spellStatus`
   （复用现有 watcher #2 的解析逻辑，useSpellSync.ts:80-91）。
4. 持久化指针，响应式链路（横幅、弹窗、计算池）自动跟随。

弹窗内按钮直接调用 store 的 `setMainUser`（`useSpellSync` 是全局单例），
依赖现有 props 回流 watcher（PartyModal.vue:92-115）刷新弹窗本地镜像。

## 4. 改动面

### `src/lib/useSpellSync.ts`（核心）

1. watcher #1（主页勾选 → 文本框，:69-77）：写入目标从 `user1Spells` 泛化为
   指针所指 blob；隐藏态跳过判断改查所指槽位三态。
2. watcher #2（文本框编辑 → 重建存档，:80-91）：监听对象泛化为所指 blob
   （指针 >0 时是 `partyData[k-1]`）；沿用现有 stringify 去重防止
   「存档 → 文本 → 存档」循环。
3. watcher #3（取消隐藏 → 对齐，:94-103）：同上泛化。
4. `handleStatusChange` / `handleBatchStatusChange` 的队友同步循环（:211-228）：
   **必须跳过指针所指槽位**——它的数据已由 `spellStatus` 表达，不跳过会重复写入。
5. 新增：`mainUserSlot` ref + 持久化 watch、`setMainUser` action、
   派生状态 `mainUserName`（供横幅与徽标用）、空指针兜底
   （所指槽位不存在时回落 0）。

### `src/components/PartyModal.vue`

- 每个队友行名字右侧加「设为我」文字按钮（维护者指定的位置）；用户 1 行同位置
  显示置灰「当前」标记；空槽位按钮禁用。
- `removeTeammate`（:189-194）：删除指针所指队友时，指针重置为 0，存档从槽 0
  文本重建（回到原「我」）。被删用户的会话勾选随删除丢弃——与现行「删除即
  丢弃该队友数据」语义一致。
- `resetParty`（:161-174）：指针重置为 0。
- 文案跟随指针：`displayName`（:367-371）、用户 1 占位符（:579）、
  帮助文本（:496-503，「用户 1 默认为当前使用者」改为描述可切换）。

### `src/App.vue`

- 主页横幅：指针 ≠ 0 时在侧栏顶部显示「当前以「{mainUserName}」的视角浏览」，
  附「切回」动作（调 `setMainUser(0)`）；复用 `sponsor-banner` 样式（:242）。

无构建配置改动（纯前端运行时逻辑），三渠道产物不受影响。

## 5. 边界规则（已确认）

1. **空队友槽**：「设为我」禁用（没有数据可切换）。
2. **切到隐藏态（2）的队友**：允许，语义 = 决策 4 的三条（不进计算池、文本框
   冻结、取消隐藏即对齐），不发明新行为。
3. **切换无确认弹窗**：指针模型无损可逆，弹窗是噪音。
4. **按钮形态**：文字按钮「设为我」，尺寸对齐行内现有小按钮；行内拥挤再降级为
   图标 + tooltip。

## 6. 明确不做（本期外）

- 多标签页预览 / `?as=` 参数 / `storage` 事件跨页同步
- 跨设备分享链接（URL 携带数据）
- `/user/{id}` 任何形式的路径路由
- 存量「双标签页静默互覆」隐患的修复
