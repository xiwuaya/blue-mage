# 「多队伍组合推荐」UI 实施计划（按你的决策更新）

## 已确认的显示与交互决策
- **每队一行**：每行 `队伍N ＋ 成员徽章们 ：共可学习 X 个技能`（X 为该队真实共同技能数，文档 §43；竖排各队，不再用「＋」跨队连接）
- 每队编号后显示成员名徽章（复用现有 `.user-badge` 样式）
- DFS 用 **Web Worker** 后台跑：界面不冻结、显示已耗时、计算中再次点击按钮=取消
- N%M≠0 时结果末尾显示「排除：xxx」灰色徽章行
- 暂不做「应用该配置」按钮（文档 §44 留待后续设计）

## 改动文件

### 1. 新增 `src/lib/partyGrouping.worker.ts`（Worker 封装）
- `onmessage` 收到 `FindBalancedPartyGroupsInput`（Map 可结构化克隆），调用 `findBalancedPartyGroups`，回 `{type:'done', result}` 或 `{type:'error', message}`。
- env.d.ts 已有 `vite/client` 引用，`?worker` 导入有类型；Vite 2.9 支持 worker 打包。

### 2. `src/components/PartyModal.vue` 脚本改动
- **行为保持重构**：把 `bestParty` 的数据准备段（activeUsers/mustIncludeMask/spellMasks，现 222-280 行）原样提取为 `buildAlgoInputData()`，新旧功能共用；Gosper 枚举、评分、返回结构一行不动。
- 新增第 5 节「多队伍组合推荐」：
  - 状态机 `idle / computing / done / error` + 结果 + 已耗时（0.1s 步进计时器）。
  - `startMultiTeamCompute()`：computing 中点击=取消；否则校验 m（1-8，未填禁用按钮）、n>30 报错 → 构建输入 → 起 Worker → postMessage。
  - onmessage/onerror 后清理 Worker 与计时器；`onBeforeUnmount` 兜底。
  - 失效策略：watch 输入签名（JSON.stringify computed：成员技能/三态/过滤分类/队伍人数），变化即重置为待计算，防陈旧结果。
  - `displayName(originalIndex)` 与现模板 394 行取名逻辑一致；`multiTeamRows` 不再切行（每队一行）。

### 3. 模板（插入 `.best-party-result` 之后、同一 `.algo-content` 内）
- 标题「多队伍组合推荐」+ 一句说明 + 按钮（`开始计算/重新计算/取消计算`）+ computing 耗时提示。
- 结果区每队一行：`队伍N`（金色标签）+ 成员徽章 + `：共可学习 <金色数字> 个技能`；末尾排除行（仅有时显示）。
- 无解/错误提示行复用 `.no-skills-tips`。

### 4. 样式（scoped CSS 追加）
`.multi-team-*` 系列，沿用金色 #ffbe31 主色与虚线分隔风格。
